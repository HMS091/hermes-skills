# 复刻生意规划（对标研究 → 三件套交付）

## When to Use（触发场景）
用户（非技术背景、中文、价格敏感、要求真实数据+负面风险）说「查查X公司……开一模一样的一家要什么流程、多少钱……写分析报告和招商/融资计划书」。这是反复出现的一类任务，不是一次性的。

## 交付三件套（一份都不能少）
1. **深度分析报告**（看懂标的）：结论先行一页 → 公司基本面（含融资口径核实）→ 产品/商业模式拆解 → 财务数据时间线（每条带来源+日期）→ 丑闻/负面事件 → 竞争格局表（费率/费用/寿命趋势）→ 复刻可行性与成本 → 风险清单 → 数据来源章节。
2. **招商融资计划书**（拿去融资）：项目速览表（定位/对标/融资需求/用途/里程碑/退出）→ 市场数据锚点 → 产品三阶段规划 → 三档收入预测（保守/中性/乐观，假设锚点写明）→ 团队方案 → 预算明细 → 融资方案（SAFE/cap/回报逻辑）→ 风险对策 → 合规免责。
3. **0-1 到 1-100 操作手册**（照做）：总路线图表（每阶段 = 时间+融资+动作+验收KPI+不过关怎么办）→ 逐阶段详解（先做什么后做什么、钱花在哪）→ 24 个月资金总账（标准 vs 省钱两路径对比）→ 合规红线清单 → 十大死法（带真实案例）→ 30/60/90 天执行清单 → 附录名词白话解释。

## 用户铁律（被「太简单、似懂非懂」打回过的写法，别再犯）
- **步骤细到可执行**：先做什么、后做什么、每阶段融多少钱、钱花在哪、验收标准、不过关怎么办。只给概念和框架会被打回重写。
- **每章/每阶段末尾必须有 go/no-go 检查点**，附「不过关怎么办」——这是用户最看重的一列，也是防烧钱的核心设计。
- **白话解释一切专业名词**（SAFE、MVP、RBAC、MEV、多签、RPC……），附录放名词表。用户不懂代码。
- 结论先行、表格优先、全中文；金额给区间并标注年份；推算必须写「推算」，数据必须带来源+日期。
- 负面风险不回避且放显眼位置（红色/加粗）：平台寿命、费率战、政策红线、丑闻案例——投资人更信这种写法。
- 涉及面向中国大陆的加密/金融业务，必须写合规红线：离岸主体、非托管、无人民币通道、无代币私募、区域屏蔽。
- 融资节奏默认阶梯验证：自有 $2–5万 → 种子 $15万 → $35万 → A轮 $200–500万，每笔钱在上一关验收通过后才放款。
- AI 角色边界话术（用户会追问）：AI（Claude Code/Codex/AI 开发平台）能替「打工的活儿」（审外包代码、出原型、写测试），替不了「签字的责任」（事故担责、凌晨救火、见投资人）——方案是 AI 扛日常 + 兼职技术顾问拿 3–8% 股权扛责任。

## 调研数据源与陷阱
- 加密交易平台/终端收入：DeFiLlama 协议适配器（经 Blackroom Alpha / OpenChainBench / MemeFees 读取，终身数据受适配器起始日限制不回溯）、Odaily 收入拆解文、YC 公司页（MRR/净利口径）、ZachXBT 帖子（累计收入口径）。
- 竞品寿命数据是风险章节的核心证据，主动搜：月费用从峰值崩跌的案例、停摆案例、巨头收购案例。
- 融资/收入口径陷阱与支付通道核验见 web-research 技能的 `references/business-company-research.md`。
- GitHub 上找「现成引擎」前先认清：平台业务层（撮合/返佣/RBAC/多用户 API）全行业没有开源，见 untrusted-code-audit 技能的 `references/crypto-trading-repo-audit.md`。

## 交付格式
- 三份 docx（docx skill）：表格样式 Light Shading Accent 1，红色 Warn 样式标风险，末尾「数据来源」章节，生成后跑 set_eastasia_font.py。
- 聊天回复 = 精炼版总路线图 + 每笔钱用途摘要 + 文件绝对路径（TUI 无附件通道）。
